# Clinic-presentable LP

Owner priority: present the LP first; align iOS/Android releases later. The existing `/lp/` is reused, with its brand, characters and standard sign-in handler retained.

LP covers daily use, all major recording/learning features, labelled illustrative screens, on-device storage and optional long-term score graphs. It does not claim cloud migration, medical measurement or treatment efficacy. It explains clinic introductions as an app/service referral programme with operator confirmation and agreed payout terms.

Attribution reuses `src/js/refpartner.js` and its shared `YEStorage` key. LP app links and kimito partner/premium links preserve the partner code; store links and other origins do not receive it. A query code alone does not confirm a referral or create a commission. Existing backend registry, sign-in attribution, billing verification and operator processes remain responsible for confirmation. No new checkout, webhook, payout, permissions or native release is implemented here.

Validation: existing and referral tests; desktop and 375px browser inspection; image loading, main app/clinic CTA visibility, no document overflow; existing auth-domain gate. New tests exercise the actual shared capture script with LP wiring, malformed codes, returning visitors, third-party origins and native commercial guards.
