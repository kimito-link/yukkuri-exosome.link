# Guideline 5.1.1(ii) — Purpose Strings リジェクト返信テンプレ

## 📋 リジェクト概要

**Apple の言い分**: 「カメラ/写真ライブラリ/マイク等の `purpose string` が
データの使い道を十分に説明しておらず、具体例も含まれていない」

**Apple が好む文面の構成**:
1. **何のための機能か**（具体的なユーザーシナリオ）
2. **具体例**（例: 〜のシーンで使う）
3. **データの保存場所**（端末内のみ / クラウド / 第三者 など）
4. **サーバー送信の有無**（明示的に書く）

**Apple が嫌う NG パターン**:
- ❌ "App needs camera access"
- ❌ "App would like to access your Contacts"
- ❌ 「ユーザー体験のため」だけ
- ❌ 「機能のため」だけ

## 🔧 コード側の修正

ワークフロー YAML の `Info.plist privacy permissions` ステップで、
3つの purpose strings をすべて「使い道 + 具体例 + 保存場所 + 送信なし」を含む形に修正：

```yaml
upsert_plist_string "NSCameraUsageDescription" "<具体的な機能名>のため、<具体例>を撮影します。例: <ユーザーシナリオ>。撮影された写真はすべてこの端末の内部（IndexedDB / localStorage）にのみ保存され、サーバーには送信されず、第三者と共有されることもありません。"
upsert_plist_string "NSPhotoLibraryUsageDescription" "<具体的な機能名>のため、写真ライブラリから<具体例>を選択します。例: <ユーザーシナリオ>。選択された写真はこの端末の内部にのみ保存され、サーバーには送信されません。"
upsert_plist_string "NSPhotoLibraryAddUsageDescription" "<機能名>のため、書き込み権限を使用します。例: <ユーザーシナリオ>。"
```

## 📝 ASC 「App Reviewに返信」 欄にコピペするテキスト（日本語版）

```
App Review チームの皆様

ご指摘いただきありがとうございます。

ご指摘の通り、これまでの purpose strings は使い道の説明が抽象的で、
具体例も含まれていませんでした。以下のとおり、3つすべての purpose strings を
「具体的な使用シーンの例」と「データの保存場所」「サーバー送信の有無」を
明示する形に更新しました。

【NSCameraUsageDescription】
<アプリ固有の文言、例：>
肌や目元の状態の変化を記録するため、ビフォーアフター写真を撮影します。
例: 今日の肌コンディションを撮影し、1か月後に同じ部位を撮って比較することで、
自分のセルフケア習慣の積み上がりを確認できます。
撮影された写真はすべてこの端末の内部（IndexedDB）にのみ保存され、サーバーには送信されず、
第三者と共有されることもありません。

【NSPhotoLibraryUsageDescription】
<アプリ固有の文言、例：>
肌や目元の変化記録に既存の写真を活用するため、写真ライブラリから過去のビフォー写真を選択します。
例: 先月撮影した目元の写真を選んで取り込み、今日撮影した写真と並べて比較できます。
選択された写真はこの端末の内部にのみ保存され、サーバーには送信されません。

【NSPhotoLibraryAddUsageDescription】
<アプリ固有の文言、例：>
アプリ内で撮影した記録写真をご自身の写真ライブラリにも保存できるようにするため、
書き込み権限を使用します。
例: クリニックの診察前に、アプリで撮りためたビフォーアフター写真を
写真アプリへエクスポートして担当医に見せられます。

このアプリは「<アプリ名>」という<アプリのジャンル>で、
すべてのデータはユーザーの端末内（localStorage + IndexedDB）のみに保存されます。
サーバーへのデータ送信、第三者への提供、広告 SDK、アカウント登録は一切ありません。

新しいビルドを近日中にアップロードしますので、ご確認のほど宜しくお願いいたします。

何かご不明な点があればお知らせください。

宜しくお願いいたします。
```

## 📝 英語版（任意の副）

```
Dear App Review Team,

Thank you for the detailed feedback on Guideline 5.1.1(ii).

We have updated all three purpose strings to include the specific use cases,
the data storage location, and an explicit statement of no server upload, as
recommended:

【NSCameraUsageDescription】
To record changes in <feature area>, this app uses the camera to take <specific
content>. For example: <user scenario>. All captured photos are stored only
inside this device (IndexedDB). They are not sent to any server and are not
shared with any third party.

【NSPhotoLibraryUsageDescription】
To use existing photos for <feature>, this app lets you select <content> from
your Photos library. For example: <user scenario>. The selected photos are
stored only inside this device. They are not sent to any server.

【NSPhotoLibraryAddUsageDescription】
To let you save record photos back to your own Photos library, this app requests
write access. For example: <user scenario>.

This app, "<app name>", is a <category>. All user data is stored only on the
device (localStorage + IndexedDB). There is no server upload, no third-party
sharing, no advertising SDK, and no account system.

A new build addressing this feedback will be uploaded shortly. Thank you for
your patience and guidance.

Best regards,
```

## ✅ チェックリスト（送信前に確認）

- [ ] `<アプリ固有の文言>` 部分を実際のアプリ名・機能名に置き換えたか
- [ ] **具体例（"例: 〜"）** がすべての purpose string に入っているか
- [ ] データの保存場所を明示したか
- [ ] サーバー送信なしを明示したか
- [ ] ワークフロー YAML 側の purpose strings も同じ内容に更新済みか
- [ ] 新ビルドの push を始めたか（返信だけでは Apple は通さない）
