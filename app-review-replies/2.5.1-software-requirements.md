# Guideline 2.5.1 — Software Requirements (Crash/Bug) リジェクト返信テンプレ

## 📋 リジェクト概要

**Apple の言い分**: 「アプリがクラッシュ」「機能が動かない」「タップしても反応しない」など、
**実機テストで実害のある不具合** を発見した。

**典型的なシナリオ**:
- 起動時にクラッシュ
- 特定タブで白画面
- ボタンが効かない
- スクロールできない / 入力できない

## 🔧 コード側の修正

```
1. リジェクトメッセージで言及されてる「再現手順」を読む
2. 実際にその手順で再現させる（Safari の DevTools、iOS シミュレータ など）
3. バグを修正
4. git push → workflow が新ビルドを上げる
```

特に注意：
- **iOS WKWebView 特有の問題**（localStorage の制限、フェッチの CORS、自動再生制限など）
- **iPhone 17 Pro Max などの新機種特有の挙動**（Dynamic Island、ノッチ周りのレイアウト）

## 📝 ASC 「App Reviewに返信」 欄にコピペするテキスト（日本語版）

```
App Review チームの皆様

クラッシュ／不具合のご報告ありがとうございます。

ご指摘いただいた事象について、以下のとおり調査・修正いたしました：

【再現環境】
- ご報告のデバイス: <iPhone モデル>
- iOS バージョン: <iOS version>
- 再現手順: <手順を引用>

【原因】
<バグの原因を簡潔に。例：「`Today` タブで XX 関数が iOS Safari 19 の API 仕様変更により
ReferenceError を発生させていた」>

【修正内容】
<具体的な修正を簡潔に。例：「該当箇所を XX に変更し、ローカル iOS Simulator で
再現しないことを確認」>

新しいビルドを近日中にアップロードしますので、ご確認のほど宜しくお願いいたします。

宜しくお願いいたします。
```

## ✅ チェックリスト

- [ ] 再現手順を実際に試したか
- [ ] バグの根本原因を特定したか（症状ではなく原因）
- [ ] 修正がローカルで動作確認できたか
- [ ] 修正範囲外で副作用がないか
- [ ] git push → workflow 起動済みか
